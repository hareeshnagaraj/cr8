cr8 — architecture

A self-hosted band music system for the music corpus archive: catalog every track, tag while listening, and give every bandmate an attributed account. Source of truth for review; reflects the system as built and running. Last updated 2026-07-30.

The problem

Years of original unreleased music in one dump: demo bounces (deliberate wav+mp3 twin pairs), 661 Ableton project folders, sidecars, stem splits. Filenames were the only metadata — but a strong convention (M-D-YY-title-key-vN) encodes date, title, key, and version on ~93% of the curated layer. No tags anywhere, no backup anywhere, and the current share tool (Samply) has no tag model at the API level. The band needs to browse, stream, tag while listening, with every judgment tied to the member who made it.

Security model (the authenticated app is a public HTTPS surface)

  • Accounts: Argon2 password hashes and individual usernames; generated member passwords are shown once; all accounts have the same full access.
  • Sessions: opaque 256-bit IDs stored only as keyed digests; HttpOnly, Secure, SameSite=Lax cookies expire after 30 days.
  • Serving: media by catalog lookup only (no client paths), resolve(strict) + containment; the service account has read-only mirror access and no access to originals.
  • Writes: same-origin session cookies plus a required custom CSRF header; autoescape, no-referrer, frame denial, request throttling, and capped Range headers.
  • Host: FileVault on, tagged Tailscale node (no key expiry), secrets in files readable only by the service account, and a nightly external authentication-boundary probe.

Design system (ratified 2026-07-29)

Forged from an 8-site reference audit (NTS, Bandcamp, Ableton, teenage.engineering, Poolsuite, Boiler Room, Samply, Untitled) → 3 archetypes → 6 token-true mockups → anti-slop pass → bake-off.

  • Base — Studio Vault: Instrument Sans + IBM Plex Mono for all metadata; soft-black #191919, gradient elevation, white-alpha text ladder; the version rail (a song's history as a tappable commit graph) is the signature move.
  • Grafts REMOVED (2026-07-30): the console (A) and flyer-poster (C) languages were grafted onto B and the result read as three grammars fighting. Owner ruling: B is the entire system. The A console table and the C poster stack (Archivo Black, 78px uppercase headlines, rotated ticket stamps) are being stripped from both surfaces.
  • Signal red means UNHEARD and nothing else. Era hues mean eras — never "selected". Selection is a weight + colour shift, never a coloured accent rail.
  • Era palette (from the artist's own album-tag history): PELICANA · NOVA1 · working — covers are generated color fields; artwork supplies all saturation, UI stays neutral.
  • Playback rulings: plain <audio> + Media Session; peaks pre-generated (never client-decoded); Safari-tab-first on iOS — add-to-home-screen never promoted (iOS 26 PWA audio regression, verified).

Coverage guarantee

"Every single track" is a checked invariant, not a claim: cr8 verify runs V1–V9 — disk↔catalog in both directions, unclassified locations fail loudly, entity closure (file → bounce → song), per-dimension tag coverage with exact gap lists, mirror integrity, remote counts, review-queue SLA, backup freshness. Nightly, with a dated report.

Decision log (the contested calls, adjudicated)

  • Build a thin app over adopting/forking a streamer — verified: no maintained OSS does attributed tag-while-listening over this catalog model. OSS-first is satisfied one layer down (every hard sub-problem uses a maintained tool).
  • Custom CLI + SQLite over beets — the song entity must be native; every hard piece is custom anyway; beets' rename/move/MusicBrainz muscles are all forbidden here.
  • mp3-320 mirror over FLAC — reuses the artist's own 586 exports byte-for-byte; losslessness is the backup's job, not the mirror's.
  • Album = song, tracklist = version history — the one thing no existing client can show; era identity via covers + tag instead.
  • One app, individual accounts — every bandmate signs in, receives full access, and owns the attribution on their tags, hearts, verdicts, and notes.
  • Tagging stays close to playback — quick chips support listening flow while the full tag editor and batch tools remain available to every member.
  • Nightly API pulls, no webhooks — a public always-on endpoint is the top silent-death candidate; at band scale, nightly is live enough.
  • rsync guarded four ways (sentinel, mountpoint, count, --max-delete) — the empty-source wipe is the classic self-hosting data-loss chain.
